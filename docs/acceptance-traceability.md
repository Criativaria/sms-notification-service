# PRD Acceptance Traceability

This matrix maps PRD functional requirements, reliability requirements, and Definition of Done (DoD) criteria to repository evidence. It distinguishes unit-test evidence, Docker-dependent integration test files, manual provider-sandbox verification, and unresolved gaps. A listed test is evidence of its stated behavior only; it does not imply full end-to-end acceptance.

## Evidence Status

| Status                                           | Meaning                                                                                                                                                                                                           |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Automated unit coverage                          | A Jest unit test exercises behavior with mocks or in-memory doubles.                                                                                                                                              |
| Automated integration coverage (Docker required) | A `*.int-spec.ts` test exercises live local infrastructure. Execution requires Docker Compose PostgreSQL/Redis and applied migrations; presence of the file does not claim it was run in the current environment. |
| Planned integration test                         | Required scenario with no corresponding Docker-backed integration test file.                                                                                                                                      |
| Manual sandbox verification                      | Requires real provider credentials and a temporary public callback URL.                                                                                                                                           |
| External blocker                                 | Cannot be verified as specified until the stated external dependency is available.                                                                                                                                |
| Gap recorded                                     | Current implementation behavior or verification does not establish the criterion.                                                                                                                                 |

## Integration Test Inventory

`npm run test:integration` is configured and currently includes these Docker-dependent files:

1. `src/database/sms-persistence.repository.int-spec.ts`: live PostgreSQL atomic message/outbox/idempotency persistence and sequential key reuse.
2. `src/modules/queue/outbox-relay.service.int-spec.ts`: live PostgreSQL and Redis relay publication plus recovery from a simulated queue publish rejection.

They require Docker Compose PostgreSQL/Redis and applied migrations. These scenarios remain required before treating associated PRD criteria as end-to-end verified:

1. HTTP ingestion validation and concurrent idempotency with PostgreSQL.
2. Transactional outbox recovery after an actual Redis outage/restart.
3. Worker retry rounds, exponential delay, provider rate limiting, DLQ insertion, and DLQ requeue with Redis and PostgreSQL.
4. Retryable mocked Twilio failure followed by mocked Bird success through the worker path.
5. Signed Twilio webhook requests updating persisted status, including duplicate callback no-ops; Bird only after its official signature contract is available.
6. Private-network enforcement through the running HTTP server and durable retention scheduling across process restarts.
